CLAUDE.md : les consignes permanentes

Ce que c'est

  • Un simple fichier texte, écrit en français.
  • Claude le lit au début de chaque session, avant votre première demande.
  • On y met les règles de la maison : écrire avec les accents, quel skill charger pour du LaTeX, à quel agent confier une erreur de compilation.

Ce que vous y gagnez

  • Vous ne répétez plus les mêmes consignes à chaque demande.
  • Le fichier se corrige au fil de l'eau : une erreur remarquée devient une règle.

Un extrait réel

## Écriture dans des fichiers LaTeX
Quand tu es appelé à écrire du code latex, tu dois
systématiquement charger le skill bfcours-latex.

## Bugs latex
Si un fichier latex bug : lance l'agent debug-tex-log
en lui donnant le fichier dont la compilation plante.
Il te dira quoi modifier.

## Langue française et accents
RÈGLE ABSOLUE : Ne JAMAIS imiter le style informel
de l'utilisateur dans les fichiers de production.
  • Des titres et des phrases courtes : c'est tout.
  • Le fichier nomme les skills et les agents à utiliser : c'est lui qui relie les briques entre elles.
  • Les règles en majuscules sont celles qu'il a fallu rappeler plusieurs fois.
Pour démarrer : « Crée-moi un CLAUDE.md pour ce dossier de cours : je suis professeur de maths en lycée, j'écris en LaTeX. »

Les skills : le savoir-faire, le cœur du dossier

Ce que c'est

  • Un dossier par tâche : écrire un QCM, monter un cours LaTeX, faire un diaporama…
  • Dedans, un fichier SKILL.md : la méthode, les pièges, des exemples. Parfois des modèles et des scripts.
  • Claude ne lit d'abord que sa description. Il ouvre le reste seulement quand la tâche s'y prête.

Ce que vous y gagnez

  • Un travail fait à votre façon, chaque fois.
  • Beaucoup de savoir-faire, sans encombrer l'assistant : il ne charge que ce dont il a besoin.
  • Un skill se partage : il suffit de copier son dossier.

Skills Détail 1 / 2

Un vrai SKILL.md : qcm-creator

---
name: qcm-creator
description: Rédige des QCM de mathématiques au
  format bfcours (environnement Mcq …) avec des
  distracteurs construits sur les erreurs réelles des
  élèves … Utiliser dès qu'il faut écrire, compléter,
  corriger ou mettre en page un QCM, … des « questions
  flash » ou des automatismes …
---

# QCM Creator — QCM au format bfcours
Un QCM bfcours s'écrit avec l'environnement `Mcq` et
la commande `\McqQuest` du paquet `rdmcq` … Charger
aussi `bfcours-latex` pour le reste du document.
  • L'en-tête (entre les ---) : le nom et la description. C'est tout ce que Claude voit en permanence.
  • La description dit quand s'en servir : « dès qu'il faut écrire… un QCM ».
  • Le corps : la méthode, lue seulement quand le skill est chargé.
  • Un skill peut en appeler un autre : ici bfcours-latex.
Skills Détail 2 / 2

Ce que contient un skill, et ce qu'est une commande

Un gros skill : bfcours-latex

skills/bfcours-latex/
├── SKILL.md      la méthode
├── references/   la doc, lue au besoin
├── scripts/      des outils qu'il lance
└── assets/       modèles, exemples

Un petit skill, comme qcm-creator, se contente de SKILL.md et references/.

Une commande = un skill réduit à un seul fichier

  • Un fichier .md dans commands/, sans dossier ni scripts.
  • On la lance en tapant son nom : commands/creer/latex/createTex.md devient /creer:latex:createTex.
  • Dans ce dossier, elles sont peu utilisées : un skill fait la même chose, et Claude le déclenche tout seul.

Les agents : des sous-assistants spécialisés

Ce que c'est

  • Un fichier par agent : son rôle, son modèle, ses outils, les skills qu'il charge.
  • L'assistant principal lui confie une tâche. L'agent travaille de son côté, puis rend un rapport.
  • Exemple : debug-tex-log lit un fichier qui ne compile pas et dit quoi corriger.

Ce que vous y gagnez

  • Les longues lectures se font ailleurs : l'assistant principal garde les idées claires pour dialoguer avec vous.
  • Plusieurs agents peuvent travailler en même temps.
  • Un petit modèle rapide pour les tâches simples.

Les hooks : des garde-fous automatiques

Ce que c'est

  • Un petit script déclaré dans settings.json, qui se lance tout seul à un moment précis.
  • Ici : avant chaque action, il vérifie qu'aucun dossier protégé n'est touché.
  • Après chaque écriture, il contrôle l'encodage du fichier. À la fin du travail, un son retentit.

Ce que vous y gagnez

  • Une règle qui ne dépend plus de la bonne volonté de l'IA : le script s'exécute à chaque fois.
  • Vos dossiers sensibles restent hors de portée.

Tout le détail dans la présentation « Mes mods : garder la main sur l'agent ».

              "Read(**/Administratif/**)" ]
  },
  "hooks": {
    "SessionStart": [ … session_hook.py ],
    "PreToolUse":   [ … guard_protected_paths.py,
                     … guard_heredoc_antislash.py ],
    "PostToolUse":  [ … check-encoding.ps1 ],
    "Stop":         [ … play-sound.ps1 ]
  }
}
MomentCe qui se passe ici
SessionStartAu démarrage : rappeler, s'il le faut, de faire le tri dans la mémoire.
PreToolUseAvant chaque outil : refuser l'accès aux dossiers protégés, et les commandes qui perdraient des antislashs LaTeX.
PostToolUseAprès une écriture : vérifier l'encodage UTF-8.
StopQuand Claude a fini : un son.

Les serveurs MCP : de nouveaux outils

Ce que c'est

  • Un petit programme qui ajoute des outils à Claude, comme une prise sur laquelle on branche un appareil.
  • Ici : compiler un document LaTeX et lire son journal d'erreurs, chercher une commande dans mes paquets LaTeX, consulter un référentiel de compétences, remplir le cahier de textes.

Ce que vous y gagnez

  • Claude agit sur vos vrais outils, avec vos réglages.
  • Un même serveur sert à plusieurs skills et agents.

La mémoire : ce qu'il a appris de vous

Ce que c'est

  • Quand vous le corrigez, Claude note la leçon dans une petite fiche.
  • Un sommaire, MEMORY.md, est relu à chaque session. Les fiches, elles, sont ouvertes au besoin.
  • Elle est rangée dans ~/.claude/projects/, un dossier par projet.

Ce que vous y gagnez

  • Une remarque faite une fois n'est plus à refaire.
  • Ce sont des fichiers texte : vous pouvez les lire, les corriger, les effacer.

Mémoire Détail 1 / 1

Une fiche de mémoire réelle (abrégée)

---
name: feedback-point-final-items-phrases
description: "Point final dans les items de liste
  LaTeX : seulement quand l'item est une phrase,
  jamais après une expression mathématique nue"
type: feedback
---
Dans les listes bfcours, un item ne prend un
point final que si c'est une phrase. Un item
réduit à une expression mathématique nue
(`$2^{12}$`) n'en prend pas.

Why: le point collé à une formule se lit comme un
symbole mathématique parasite …
  • Une fiche = une leçon, avec sa raison (Why) : Claude sait quand l'appliquer.
  • Types de fiches : préférences, projets en cours, références utiles.
  • Quand une leçon vaut pour tous les projets, elle remonte dans un skill ou dans CLAUDE.md.
Le skill memory-distiller fait périodiquement le tri : il regroupe, il épure, il propose ce qui mérite de devenir une règle.

Comment ça s'articule

Le professeur « Ajoute un QCM de 12 questions sur les fonctions affines à ma fiche. »
1. Il relit les consignes
CLAUDE.md et la mémoire : accents, LaTeX bfcours.
2. Il charge un skill
La description de qcm-creator correspond : il lit sa méthode.
3. Il délègue
Un agent rédige le QCM de son côté, puis rend compte.
4. Un hook surveille
À chaque lecture ou écriture : dossiers protégés, encodage.
5. Il vérifie
Il compile la fiche avec un outil MCP et corrige les erreurs.
La fiche, avec son QCM, compilée

Vous n'avez rien eu à préciser : tout était déjà écrit dans le dossier.

Pour un projet, ou pour tous ?

.claude/ du projet recommandé

Dans le dossier de travail, par exemple celui de l'année.

  • CLAUDE.md à la racine du dossier.
  • Presque tout : skills, agents, hooks du projet, serveurs MCP.
  • Actif seulement quand on lance Claude Code dans ce dossier.

~/.claude/ global

Dans votre dossier personnel, pour tous les projets.

  • Un CLAUDE.md global : les règles valables partout (ici, la prudence avec le navigateur).
  • Un settings.json global : ici, le hook qui envoie les suppressions à la corbeille.
  • La mémoire, un dossier par projet.

Règle simple : ce qui touche à votre métier va dans le projet ; seuls les garde-fous universels vont dans le global.
