La corbeille au lieu de l'effacement

Ce que fait l'agent

  • Il lance une suppression, comme d'habitude.
  • Le hook l'intercepte avant qu'elle s'exécute.
  • Les fichiers partent à la corbeille Windows au lieu d'être effacés.
  • La commande passe sans vous demander la permission : elle est devenue réversible.

Ce que vous y gagnez

  • Une erreur de l'agent se répare : on restaure depuis la corbeille.
  • Vous choisissez vous-même ce qui arrive quand l'IA lance une commande que vous jugez dangereuse.
  • Un hook sans interface, actif dans tous vos projets.

Corbeille Détail 1 / 2

Comment ça marche

Un hook PreToolUse sur les outils Bash et PowerShell. Il ne touche qu'aux commandes qui contiennent une suppression.

  • Bash : il place en tête du PATH un rm de substitution. Cela couvre aussi xargs rm et find -exec rm.
  • PowerShell : il définit une fonction Remove-Item prioritaire. Les alias rm, del, ri, rd, erase, rmdir y mènent.
  • Le rm de substitution reprend -f, -r/-R et --. Comme le vrai, il refuse un dossier sans -r.

Déclaré dans ~/.claude/settings.json, outils Bash|PowerShell.

// ~/.claude/hooks/pre-tool-corbeille.mjs (extrait)
if (outil === 'Bash' && /* contient rm */) {
  prefixe = `export PATH='…/corbeille/bin':"$PATH"; `;
} else if (outil === 'PowerShell' &&
           /* Remove-Item, rm, del… */) {
  prefixe = /* charge remove-item.ps1 */;
}
if (!prefixe) process.exit(0); // rien à changer

// Décision rendue à Claude Code :
permissionDecision: 'allow',
permissionDecisionReason:
  'suppression redirigée vers la corbeille Windows',
updatedInput: { command: prefixe + cmd }

Ses limites, et comment l'obtenir

Limites

  • Rien n'est libéré sur le disque tant que vous ne videz pas la corbeille.
  • Un élément plus gros que la capacité de la corbeille peut être effacé directement par Windows.
  • Une suppression faite dans un script Python (shutil.rmtree, os.remove) ou directement en .NET ne passe pas par le hook.
Vous « Écris-moi un hook global qui envoie à la corbeille tout ce que tu supprimes avec rm ou Remove‑Item. »
Vérifiez-le sur un dossier d'essai : demandez à Claude de le supprimer, puis retrouvez-le dans la corbeille.

Des dossiers hors de portée

Ce que fait l'agent

  • Vous dressez la liste : « Copies des élèves », « Notes », « Administratif »…
  • Avant chaque action, le hook vérifie qu'elle n'y touche pas.
  • Si elle y touche, elle est refusée, avec un message qui explique pourquoi.

Ce que vous y gagnez

  • Un degré de certitude sur vos données sensibles.
  • Valable quel que soit le mode de permission.
  • Vous seul modifiez la liste : l'agent ne peut pas y toucher.

Dossiers interdits Détail 1 / 3

La liste : .claude/protected-paths.json

// exemple anonymisé
{
  "protected_directories": [
    "Administratif",
    "D:/Notes",
    "D:/Classes/*/Notes"
  ],
  "protected_allowlists": [
    { "root": "D:/Copies des élèves",
      "readable": ["anonymes"] }
  ],
  "trusted_scripts": [
    { "chemin": "outils/export.py",
      "sha256": "3f9a…" }
  ],
  "block_broad_recursive_shell": true
}
  • protected_directories : les dossiers interdits. Un nom relatif, un chemin absolu, ou un motif avec *.
  • protected_allowlists : un dossier interdit (root), sauf quelques sous-dossiers lisibles malgré tout (readable), par exemple des copies anonymisées.
  • trusted_scripts : des scripts autorisés, épinglés par leur empreinte. Modifié après l'épinglage : refusé.
  • block_broad_recursive_shell : surveiller les parcours récursifs des commandes.
Le fichier est lui-même protégé : l'agent ne peut pas le modifier. Seul le professeur le modifie, et seul le professeur épingle un script.

Ce qui est contrôlé

AccèsCe que vérifie le hook
Outils fichiers de ClaudeRead, Edit, Write, Glob, Grep : le chemin visé.
Commandes shellcat, python, grep… en Bash comme en PowerShell : les chemins lus et parcourus.
Scripts lancéspython x.py, node x.js… : le script est lu et analysé. Refus s'il cite le dossier, même reconstitué par concaténation, ou s'il parcourt récursivement le projet ou un dossier parent.
Liens et jonctionsRésolus avant la vérification. Créer un lien vers un dossier protégé est refusé.
Contrairement aux règles permissions.deny de settings.json, il s'applique dans tous les modes de permission, y compris le mode « bypass », et couvre aussi les commandes shell.
Le même hook garde aussi les fichiers .env, refuse git push --force et les suppressions trop larges.

Ses limites, dites franchement

Refuser seulement sur preuve

  • Le hook refuse ce qu'il voit : un nom ou un chemin protégé, un parcours dont la racine connue englobe un dossier protégé.
  • En cas de doute (un chemin rangé dans une variable, par exemple), il laisse passer.
  • Un script absent ou illisible n'est pas bloqué.

Choix assumé : un garde-fou qui refuse au moindre doute bloque l'agent sans cesse.

Une analyse, pas un verrou

  • Le hook analyse la commande avant qu'elle s'exécute. Ce n'est pas un verrou du système.
  • Pour une garantie absolue, il faudrait des droits Windows sur les dossiers (ACL). Piste étudiée, non déployée.
  • Hook de projet : déclaré dans le .claude/settings.json du projet.

Des recherches qui contournent l'interdit

Ce que fait l'agent

  • Il cherche dans tout un dossier, qui contient un dossier interdit.
  • Au lieu de refuser, le hook réécrit la recherche pour exclure ce dossier.
  • Le résultat revient sans les fichiers interdits.

Ce que vous y gagnez

  • L'agent travaille normalement, sans être bloqué.
  • Rien ne fuit.

Recherches filtrées Détail 1 / 2

Avant / après : la commande réécrite

Exemples tirés des tests du hook, avec un dossier interdit nommé « Administratif » :

L'agent lanceLe hook exécute à la place
grep -rn motif .grep --exclude-dir='Administratif' -rn motif .
find . -name '*.tex'find . \( -path './Administratif' -prune \) -o \( -name '*.tex' \) -print
rg --no-ignore motif .ajout d'un filtre -g '!…' qui écarte le dossier

Dans la commande réelle, le nom est écrit sous forme de motif ([A]dministratif), pour ne pas déclencher les autres règles de refus.

Quand la réécriture est impossible, la commande est refusée : find . -delete (incompatible avec l'exclusion), find -L (suit les liens), ls -R . (non réécrit).
Recherches filtrées Détail 2 / 2

Et les outils de recherche de Claude ?

Dossier interdit relatif

Exemple : « Administratif », à la racine du projet.

  • Les outils Grep et Glob de Claude respectent le fichier .ignore du projet : un dossier qui y est listé n'est pas parcouru.
  • Même chose pour rg lancé sans --no-ignore.

Dossier interdit absolu

Exemple : D:/Copies des élèves.

  • Une recherche Grep dont la racine englobe ce dossier est refusée.
  • Le message propose de cibler un sous-dossier lisible (par exemple les copies anonymisées).
  • Un motif Glob qui pourrait désigner son contenu est refusé de la même façon.

Ce que vous y gagnez

Sérénité
Les suppressions sont réversibles : une erreur se rattrape.
Confidentialité
Copies, notes, documents administratifs : hors de portée de l'agent.
Fluidité
Moins de demandes de permission, et un agent qui n'est pas bloqué.

Vous fixez les règles une fois. L'agent travaille ensuite librement, à l'intérieur de ces règles.
